Question sets: POST /api/sessions/{sid}/batch (stream format and config keys)

Answers a list of questions in one request. The questions are independent of each other and of the chat so far (no follow-up context) and run in parallel, batch_concurrency at a time. The chat needs a ready document.

Request

POST /api/sessions/{sid}/batch
Content-Type: application/json
Accept: text/event-stream

{"questions": ["What is the management outlook?", "What are the principal risks?"]}

Blank questions and exact duplicates are dropped; at most max_batch_questions remain (see GET /api/config), each up to 4000 characters.

Events (Server-Sent Events)

The same events as POST .../messages (step, step_done, token, citation, answer_done, eval_started, eval_result, eval_done, error), interleaved across questions. Every one carries message_id (which answer it belongs to) and the added integer index (0-based position in the set). message_start is not sent; batch_start replaces it.

  • batch_start comes first: {"items": [{"index": 0, "question": "...", "user_message": {...}, "message_id": "..."}, ...], "concurrency": 3}. All rows already exist, in order.
  • error with a message_id fails that one question only (the others continue).
  • batch_done: {"answered": 4, "failed": 1}, once every answer is finished.
  • done comes last, after every answer has been scored or skipped.
event: batch_start
data: {"items": [{"index": 0, "question": "...", "user_message": {...}, "message_id": "a1"}], "concurrency": 3}

event: token
data: {"message_id": "a1", "index": 0, "text": "Revenue "}

Errors before the stream starts (JSON)

400 empty_question (nothing left after cleaning), 400 too_many_questions, 402 budget_exhausted, 403 demo_read_only, 404 session_not_found, 409 session_busy / document_not_ready, 429 rate_limited (the set costs one question per item against the hourly allowance; too few left refuses the whole set).

Config keys (GET /api/config)

  • default_questions: the owner's question set offered after an upload (array of strings).
  • max_batch_questions: the most questions one request may run.
